# Отчёт о тестировании MineHunter 1.0.0

Всё, что здесь написано, проверено на этой машине и подтверждается файлами в `research/` и выводом `MineHunter-cli.exe selftest`. Где чего-то не проверяли — сказано прямо (раздел 9).

**Стенд:** Windows 11 Home 25H2 (сборка 26200), x64, 24 логических ядра, права администратора. В системе: Защитник Windows не запущен и другого антивируса нет, UAC выключен, брандмауэр выключен для одного профиля, SmartScreen отключён (MineHunter сообщил об этом сам).

## 1. Встроенные автотесты — 55 из 55

`MineHunter-cli.exe selftest` (внешняя сеть не используется — сквозной тест обновлений поднимает сервер на 127.0.0.1; система не меняется, временные файлы удаляются):

| Группа | Что проверяется |
|---|---|
| Пути и классы | нормализация, классы `%TEMP%` / System32 / Program Files / ProgramData / AppData, «легальная» установка в `Local\Programs`, гомоглифы (`ReaItekHD` → realtek), выделение exe из командной строки |
| Правила и сканеры | загрузка набора правил (в т. ч. из замаскированного ресурса), поиск строк ASCII и UTF-16, командная строка майнера ловится, **6 безобидных командных строк (Chrome, Node, Python, svchost, Docker, java --algo test) не ловятся**, обнаружение исключений Защитника, разбор PE, проверка подписи (`notepad.exe`), честное «этот билд не подписан» |
| Доверие издателей | настоящие названия (`Intel Corporation`, `NVIDIA Corporation`, `ASUSTeK…`, `Valve Corp.`) проходят; двойники (`Intelligent Systems Ltd`, `Pineapple Corp`, `Free Intel Miner LLC`) — **нет** |
| Калибровка риска (защита от ложных срабатываний) | «неподписанный + Temp + высокая нагрузка» → чисто/низкий; доверенная тяжёлая программа → чисто; много слабых признаков → не выше «подозрительно»; один громкий сигнал без подтверждения → не выше «подозрительно»; полная командная строка майнера → высокий риск; майнер + автозапуск + маскировка → вредоносное; поддельный svchost → высокий риск; неприметная программа с четырьмя признаками сразу → высокий риск; известный хеш → вредоносное; доверие не отменяет поведение процесса |

| Реестр | значения и подразделы переживают экспорт → JSON → импорт |
| Обновления | сравнение версий; подпись правил проверяется, изменённый пакет отклоняется; **сквозной сценарий с локальным сервером**: новая версия объявляется, подписанный пакет скачивается/проверяется/ставится, тот же номер = «последняя», пакет с неверным SHA-256 / чужой подписью / без подписи (при заданном ключе) **отклоняется**, http к нелокальному хосту отклоняется, недоступный сервер = «нет сети» |
| Отчёты | пустой отчёт сериализуется в JSON и текст |

## 2. Реальная система: калибровка на ложные срабатывания

Главное требование: обычные программы не считаются вирусами. Процесс шёл итерациями по реальным прогонам:

* **Первая Быстрая проверка (черновые правила):** 1 «высокий риск», ≈ 40 «подозрительных», 60 заметок — почти всё ложные срабатывания: образы .NET, созданные самой Windows (NGEN), Minecraft/Java, Chrome for Testing, репаки и инсталляторы во временных папках, файлы в Корзине, списки блокировки в расширении антивируса (принимались за майнер), повторяющиеся копии, слабые сигналы автозапуска.
* **Исправления** (каждое — причина, а не «замазывание»): NGEN-образы = доверие; инсталляторы во временных папках не подозрительны; «поддельные сведения о версии» — только для файлов, выдающих себя за компонент Windows (точная строка продукта «Microsoft® Windows® Operating System»), а не для любого «Microsoft DirectX/Google Dawn»; списки блокировки (JSON/текст) — данные, а не код майнера, антивирусные расширения пропускаются; копии файла усиливают подозрение только если файл и так подозрителен (порог 30 баллов); соотношение весов автозапуска; скрипты-помощники подписанных продуктов (Node.js `install_tools.bat`) с шаблоном «скачать и запустить» — вес снижен втрое; доверие издателю — только по началу названия сертификата с границей слова; «призрачные» записи Планировщика без XML — вес 2 (настоящий приём скрытия — удалённый дескриптор `SD` — вес 40).
* **Итог Быстрой проверки (финальная сборка, чистая система, 59 с):** **2 находки высокого риска — обе настоящие**, 0 подозрительных, 21 мелкая заметка:
  * `%APPDATA%\Update\conhost.exe` (64): скрытый+системный неподписанный .NET-файл 2,2 МБ под именем системного `conhost.exe`, энтропия 6,8, без сведений о версии;
  * `%LOCALAPPDATA%\driverswin\system92\ex_567221_758.ps1` (73): скрипт, добавляющий исключения Защитника на диск/системную папку, в папке-двойнике `system92`.
  Оба — остатки прежнего заражения (даты файлов 21.05.2026); MinerSearch их не показывал. **Файлы не удалялись и не изменялись** — решение за владельцем машины.
* **Полная проверка (все диски, ≈ 82 000 файлов):**

| Прогон | Время | Проверено / из кэша | Прочитано | Итог |

## 4. Обезвреживание, карантин, восстановление (только на объектах лаборатории)

* `scan --quick --fix --yes … --only MinerLab` (два прохода: сначала «высокий риск», затем `--min suspicious --all-steps`): **26 шагов, все успешны** — остановка 5 процессов, перенос 9 файлов в карантин (в т. ч. запущенных: сначала процесс замораживается и останавливается, потом файл уходит в карантин), удаление 4 задач, 2 ярлыков автозагрузки, 2 служб, 2 Run-значений, 2 WMI-подписок. Повторный автоматический скан подтвердил: «процесс исчез, файлы обезврежены, автозапуск удалён» для всех находок (`research/mh_lab/fix1`, `fix2`).
* Реальные остатки заражения (`conhost.exe`, `ex_…ps1`) не трогались: `--only MinerLab` ограничивает обезвреживание.
* Разница снимков системы (службы, задачи, WMI, Run, ярлыки, папки) после обезвреживания: остались только объекты, у которых не было вердикта (S04–S07, HKLM Run…) и пустая папка задач.
* **Восстановление из карантина:** все 21 элемент возвращён (21 из 21); SHA-256 всех **24 лабораторных файлов** совпал с исходным; задачи (в т. ч. скрытая и под `\Microsoft\…`), службы, WMI (фильтр + потребитель + привязка), значения Run, ярлыки — вернулись; разница снимков «до обезвреживания» и «после восстановления» — только не относящиеся к лаборатории изменения (журнал MineHunter, состояние служб).
* Через GUI: `--neutralize MinerLab` — обезвреживание выполняется, выводится «Результат обезвреживания» с отметкой «удалено и проверено», список находок обновляется (`research/gui/cleanup_ru.png`).
* **Не проверялось на живом образце:** сценарий «нужна перезагрузка» (удаление занятого файла при следующем запуске) реализован через `MoveFileEx`, но занятый неубиваемый процесс в лаборатории не воспроизводился.

Кнопка «Выборочная проверка» (диалог выбора папки) вручную не нажималась. Защита от двойного запуска (мьютекс) реализована, но не проверялась.

## 6. Совместимость с другими сканерами (найдено при сравнении)

MinerSearch пометил `MineHunter.exe` как «Malicious file»: в exe лежал открытый список майнерских строк (правила детекта). Исправлено: правила внутри exe хранятся сжатыми и замаскированными (XOR), читаемый исходник остаётся в `rules/core.json` (JSON он не проверяет). Проверено «оракулом» (MinerSearch на одной папке): релизные `MineHunter.exe` и `MineHunter-cli.exe` **не помечаются**. Тот же класс ошибки нашёл и сам MineHunter: при проверке лаборатории он пометил собственные копии `MineHunter.exe` как «Cryptominer files» (14 маркеров: в коде оставались слова из тестов и регулярного выражения). Слова убраны из кода (правила — данные, тесты собирают строки во время выполнения), а автотест теперь проверяет, что в собственном exe **0 маркеров** (`MineHunter-cli.exe markers MineHunter.exe` показывает список маркеров любого файла). Это защита от ложных срабатываний других сканеров; настоящий антивирус (Defender и др.) на этой машине выключен, поэтому его реакцию на неподписанный exe проверить нельзя — при публикации на GitHub рассмотрите подпись кода.

## 7. Самозащита и приватность (проверено)

* Папка данных `%ProgramData%\MineHunter`: SYSTEM и администраторы — полный доступ, обычные пользователи — только чтение (`icacls`).
* `scan.lock` (прерванный скан), SHA-256 собственного exe до/после скана — в отчёте.
* Сеть: только `GET` публичного `version.json`/пакета правил; в автотесте проверено, что http к нелокальному хосту отклоняется. **Замер:** пока шла проверка, `tests/tools/probe_network.ps1` каждые 0,7 с опрашивал TCP-соединения и UDP-порты процесса MineHunter (92 выборки за ≈ 65 с): **ни одного** (адрес обновлений не задан). Телеметрии, аккаунта, отправки файлов/хешей/журналов нет (в коде нет соответствующих вызовов; единственный `HttpClient` — в `Updater`).

## 8. Особенности среды тестирования (не дефекты программы)

* Тестовые команды запускались из среды, которая виртуализирует `HKCU\Software` и `%APPDATA%`/`%LOCALAPPDATA%` (запись уходит в приватный слой пакета и не видна другим процессам). Из-за этого один цикл «обезвредить → восстановить» сначала показал «пропавшие» Run-значения; повтор в едином контексте доказал, что восстановление работает. Виртуализованные лабораторные хвосты после тестов удалены. Обычная установка программы такой виртуализации не имеет.
* MinerSearch после тестовых запусков имел счётчик запусков 20 (был 10) и дополнительные логи; счётчик возвращён к 10, прежние логи не тронуты.

## 9. Что НЕ проверено (честно)

* Реальные образцы вредоносного ПО не запускались (нельзя на этом ПК) — вместо них лаборатория. Точность на «живых» семействах определяется правилами и будет улучшаться обновлениями.
* Реакция Defender/других антивирусов на программу; работа на Windows 10 и на 4-ядерных/слабых машинах; влияние на игры.
* Восстановление после перезагрузки для занятых файлов (см. п. 4), обновление по настоящему GitHub-адресу (пока не задан; все ветки проверены на локальном сервере), кнопка выбора папки.
* Ядерные руткиты и полностью зашифрованные образцы без следов — по построению не гарантируются.
