# Отчёт о тестировании, версии 1.0.0 и 1.1.0

Все результаты получены на одном компьютере: Windows 11 Home 25H2 (сборка 26200), x64, 24 логических ядра, права администратора. Защитник Windows не запущен, другого антивируса нет, UAC выключен, брандмауэр выключен для одного профиля, SmartScreen отключён (MineHunter показал это в блоке состояния). Сырые журналы прогонов в репозиторий не входят, здесь приведены итоги. Что не проверялось, указано в разделе 9 (для 1.0.0) и 12.7 (для 1.1.0). Разделы 1–11 описывают версию 1.0.x; результаты версии 1.1.0 собраны в разделе 12.

## 1. Самотест

`MineHunter-cli.exe selftest` в сборке 1.0.0 выполняет 60 проверок, все проходят. Число выводится в конце запуска и зависит от сборки. Сеть не используется: проверка обновлений идёт к серверу на 127.0.0.1. Вне временной папки система не меняется.

| Группа | Что проверяется |
|---|---|
| Пути | Нормализация, классы `%TEMP%`, System32, Program Files, ProgramData, AppData, установка в `Local\Programs`, гомоглифы (`ReaItekHD` даёт `realtek`), выделение exe из командной строки. |
| Правила и сканеры | Загрузка пакета правил (в том числе из замаскированного ресурса), поиск строк ASCII и UTF-16, срабатывание на командную строку майнера, 6 безобидных командных строк не срабатывают (Chrome, Node, Python, svchost, Docker, `java --algo test`), исключения Защитника, разбор PE, проверка подписи `notepad.exe`, собственный exe без подписи, в собственном exe нет маркеров майнеров. |
| Пакеты правил | Правило из пакета с большей версией заменяет старое при любом порядке загрузки, старый пакет не заменяет; `disabledRules`; `knownGoodHashes`; `textRu`; примеры строк каждого правила (29 правил, 78 строк). |
| Доверие издателям | `Intel Corporation`, `NVIDIA Corporation`, `ASUSTeK…`, `Valve Corp.` принимаются. `Intelligent Systems Ltd`, `Pineapple Corp`, `Valverde Media LLC`, `Free Intel Miner LLC` и пустое имя нет. |
| Оценка риска | Неподписанный файл в Temp с высокой нагрузкой остаётся чистым. Доверенная тяжёлая программа чиста. Много слабых признаков не выше «Подозрительного». Один громкий сигнал без подтверждения не выше «Подозрительного». Полная командная строка майнера даёт высокий риск. Майнер, автозапуск и маскировка дают «Вредоносное». Поддельный svchost даёт высокий риск. Программа с четырьмя независимыми слабыми признаками даёт высокий риск. Известный хеш даёт «Вредоносное». Доверие не отменяет поведение процесса. |
| Решения | Критические процессы Windows не завершаются, доверенные файлы не попадают в карантин. |
| Карантин | Одинаковые файлы не перезаписывают друг друга. В хранилище лежит не исходный файл. Восстановление даёт тот же SHA-256. Повреждённая копия не восстанавливается. Удаление работает. |
| Реестр | Значения и подразделы переживают экспорт в JSON и импорт. |
| Обновления | Сравнение версий. Подпись проверяется, изменённый пакет отклоняется. С локальным сервером: новая версия объявляется, подписанный пакет скачивается, проверяется и ставится, та же версия считается последней, пакет с неверным SHA-256, с чужой подписью или без подписи отклоняется, http к нелокальному хосту отклоняется, недоступный сервер считается отсутствием сети. |
| Отчёты | Пустой отчёт сериализуется в JSON и текст. |

## 2. Реальный компьютер

Проверка шла итерациями: прогон, разбор ложных срабатываний, исправление правил.

Первая быстрая проверка с черновыми правилами дала 1 находку высокого риска, около 40 подозрительных и 60 заметок. Почти все были ложными: образы .NET, созданные самой Windows (NGEN), Minecraft и Java, Chrome for Testing, репаки и установщики во временных папках, файлы в корзине, списки блокировки в расширении антивируса (принимались за майнер), копии файлов, слабые признаки автозапуска.

Исправления:
- образы NGEN получили доверие;
- установщики во временных папках перестали быть подозрительными;
- `MASQ.FAKE_VENDOR_INFO` с весом 22 выдаётся только для точной строки продукта «Microsoft® Windows® Operating System», а не для любого файла с «Microsoft DirectX» или «Google Dawn»;
- списки блокировки (JSON и текст) считаются данными, расширения антивирусов пропускаются;
- копии файла усиливают подозрение, только если файл и так подозрителен (порог 30 баллов);
- скрипты-помощники подписанных продуктов (`install_tools.bat` из Node.js) с шаблоном «скачать и запустить» получили вес ниже втрое;
- доверие издателю проверяется по началу названия сертификата с границей слова;
- записи планировщика без XML весят 2, удалённый дескриптор `SD` весит 40.

Итог быстрой проверки финальной сборки: 59 с, 2 находки высокого риска, 0 подозрительных, 21 заметка. Обе находки настоящие, это остатки прежнего заражения:
- скрытый и системный неподписанный .NET-файл 2,2 МБ под именем `conhost.exe` в `%APPDATA%\Update` (балл 64): энтропия 6,8, сведений о версии нет;
- скрипт `ex_567221_758.ps1` в папке-двойнике `system92` (балл 73): добавляет исключения Защитника для диска и системной папки.

Файлы не удалялись и не менялись.

Полная проверка (все диски, около 82 000 файлов):

## 4. Обезвреживание, карантин, восстановление

Проверялось только на объектах лаборатории.

- `scan --quick --fix --yes … --only MinerLab` в два прохода (сначала высокий риск, затем `--min suspicious --all-steps`): 26 шагов, все успешны. Остановлено 5 процессов, 9 файлов перенесено в карантин (у запущенных сначала замораживается и останавливается процесс), удалено 4 задачи, 2 ярлыка автозагрузки, 2 службы, 2 значения Run, 2 WMI-подписки. Повторная проверка подтвердила, что процессы исчезли, файлы обезврежены, автозапуск удалён.
- Настоящие остатки заражения (`conhost.exe`, `ex_….ps1`) не затрагивались: `--only MinerLab` ограничивает обезвреживание.
- Снимок системы до и после обезвреживания различается только объектами без вердикта (S04–S07, HKLM Run) и пустой папкой задач.
- Восстановление из карантина: возвращены все 21 элемент, SHA-256 всех 24 лабораторных файлов совпал с исходным. Задачи (в том числе скрытая и под `\Microsoft\…`), службы, WMI (фильтр, потребитель, привязка), значения Run и ярлыки вернулись. Снимки «до обезвреживания» и «после восстановления» различаются только тем, что к лаборатории не относится (журнал MineHunter, состояние служб).
- Через окно: `--neutralize MinerLab` выполняет обезвреживание, показывается результат с отметкой «удалено и проверено», список находок обновляется.
- Не проверялось: удаление занятого файла при перезагрузке. Оно реализовано через `MoveFileEx`, но занятый неубиваемый процесс в лаборатории не воспроизводился.

## 5. Окно программы

Проверено по снимкам окна (служебные ключи `--shot` и `--shots`): главный экран, вкладки «Результаты» (что, где, улики с баллами, цепочка, действия с флажками), «Граф угрозы», «Карантин», «Журнал», «О программе», результат обезвреживания, языки RU и EN. Найденные дефекты вёрстки (тёмный текст на тёмном фоне на вкладке «О программе», нечитаемые подписи типов) исправлены. Диалог выбора папки (стандартный `FolderBrowserDialog`) кликом мыши не проверялся, но код за кнопкой «Выборочная» тот же `ScanMode.Custom`, что и `scan --path <папка>`: проверено на отдельной папке с одним файлом — просканирован именно он (1 файл, 0 из кэша), заметка на балл 12, не угроза. Защита от двойного запуска проверена: второй запуск `MineHunter.exe` при работающем первом экземпляре сразу показывает «MineHunter уже запущен» и завершается (код выхода 0), первый экземпляр не трогается.

## 6. Совместимость с другими сканерами

MinerSearch пометил `MineHunter.exe` как «Malicious file»: в exe лежал открытый список строк майнеров (правила детекта). Теперь правила внутри exe хранятся сжатыми и замаскированными (XOR), читаемый исходник остался в `rules/core.json`. Проверка MinerSearch на одной папке: релизные `MineHunter.exe` и `MineHunter-cli.exe` не помечаются.

Тот же класс ошибки нашёл сам MineHunter: при проверке лаборатории он пометил собственные копии как «Cryptominer files» (14 маркеров, слова из тестов и регулярного выражения остались в коде). Слова убраны из кода, тесты собирают строки во время выполнения, а самотест проверяет, что в собственном exe 0 маркеров (`MineHunter-cli.exe markers MineHunter.exe` показывает маркеры любого файла).

Реакция Defender и других антивирусов на неподписанный exe не проверялась: на тестовом компьютере они выключены.

## 8. Сеть и данные

- Права на `%ProgramData%\MineHunter`: SYSTEM и администраторы имеют полный доступ, обычные пользователи только чтение (проверено `icacls`). Карантин, список исключений и правила остаются там; отчёты из этой папки вынесены в `Reports` рядом с exe (проверено: после `scan --quick` без `--report-dir` файл `report.txt` появляется именно там, а не в `%ProgramData%`).
- В отчёте записываются `scan.lock` (прерванная проверка) и SHA-256 собственного exe до и после проверки.
- Сеть: программа делает только GET публичного `version.json` и пакета правил, http к нелокальному хосту отклоняется (проверяет самотест). Скрипт `tests/tools/probe_network.ps1` каждые 0,7 с опрашивал TCP-соединения и UDP-порты процесса во время команды `scan` (92 выборки за 65 с) и ничего не увидел; адрес обновлений при этом не был задан. Единственный `HttpClient` находится в `Update/Updater.cs`.
- Тесты запускались из среды, которая виртуализирует `HKCU\Software` и `%APPDATA%`, `%LOCALAPPDATA%`: записи уходят в приватный слой пакета и не видны другим процессам. Из-за этого один цикл «обезвредить и восстановить» сначала показал пропавшие значения Run, а повтор в одном контексте показал, что восстановление работает. Хвосты лаборатории в виртуализованном слое после тестов удалены. В обычной установке такой виртуализации нет.

## 9. Что не проверялось

- Настоящие образцы вредоносного ПО не запускались. Вместо них использована лаборатория, поэтому точность на реальных семействах определяется правилами.
- Реакция Defender и других антивирусов, работа на Windows 10 и на 4-ядерных или слабых компьютерах, влияние на игры.
- Удаление занятых файлов при перезагрузке и кнопка выбора папки.
- Ядерные руткиты и полностью зашифрованные образцы без следов не ловятся по построению.

## 10. Пакет правил 2026.09.26.1

К первому набору добавлено 22 правила командной строки (реестр, облачная защита и службы Защитника, завершение процессов антивирусов и конкурирующих майнеров, службы, задачи и Run в пользовательских папках, постоянные WMI-подписки, рефлективная загрузка PowerShell, `certutil`, `msiexec`, `mshta`, скрытый PowerShell со скачиванием, `attrib +h +s`, `icacls /deny`, `curl | cmd`), 7 путей-индикаторов мест подброса (`Windows\Fonts`, `Help`, `Debug`, `spool\drivers\color`, `System32\Tasks`, `PerfLogs`, случайные hex-папки в ProgramData) и 28 имён программ-майнеров.

- У каждого нового правила есть `samples` и `textRu`. Самотест проверяет 29 правил и 78 строк, при первом прогоне он нашёл ошибку в регулярном выражении (разделитель `;` в рефлективной загрузке).
- Регрессия на реальном компьютере (быстрая и полная проверки): новых находок нет, кроме одной. Служебный скрипт установщика стороннего антивирусного продукта вышел «подозрительным»: правило завершения процессов антивируса видело процессы самого продукта. Подобные ложные срабатывания теперь можно исправлять данными: `disabledRules`, `knownGoodHashes`, вес правила.
- Обновление против настоящего репозитория: `MineHunter-cli.exe update-check` сообщает «последняя версия», версии правил локальная и онлайн совпадают. Установку подписанного пакета с GitHub сборкой, у которой правила были старше, проверили вручную.

## 11. Задачи с действием ComHandler и пакет правил 2026.10.01.1

- Новая проверка: действия планировщика `ComHandler` (задача запускает зарегистрированный COM-класс вместо программы — без строки `Exec`, которую искали раньше). Class id ищется сначала в HKCU, затем в HKLM, как это делает сама COM-подсистема.

- Пакет правил 2026.10.01.1 добавляет 5 правил командной строки (`CMD.PS.AMSI_BYPASS` — отключение AMSI, `CMD.UAC.DISABLE`, `CMD.DEFENDER.TASK_DISABLE`, `CMD.MINER.LHR_UNLOCK` — обход ограничителя хешрейта NVIDIA, `CMD.RUNDLL32.USERPATH`) и 5 имён уязвимых драйверов, которыми пользуются BYOVD-атаки (TrueSight, Zemana zam64/zamguard, Dell dbutil_2_3). У каждого правила есть `samples`; самотест проверяет 34 правила и 93 строки.
- Регрессия на реальном компьютере (быстрая проверка, 37 с): 0 высокого риска, 0 подозрительных, 31 заметка — новых находок от сегодняшних правил нет (проверено по тексту отчёта: ни один из пяти новых идентификаторов правил и ни одно из пяти новых имён драйверов не встретились). ### 12.3. Операционные тесты

### 12.4. Состязательный набор

Каждая из 35 имитаций создаёт безвредный объект, который указывает на собственную безвредную программу лаборатории (она несколько секунд ничего не делает): значения Run, RunOnce и Policies, Windows `Load`, `AutoRun` cmd, переопределение `ms-settings`, IFEO и SilentProcessExit, Active Setup, COM-классы (в том числе скриптлет), Run, запускающий программу из потока NTFS, подмена DLL, службы (обычная, обёртка NSSM, `ServiceDll`, команда восстановления, драйвер), задачи (с переменной в пути, «в простое»), подписка WMI вне `root\subscription`, файлы (скрытый файл в автозагрузке, архив с файлом под именем майнера, скрытая и системная программа в общей папке, переопределение порядка символов в имени, двойное расширение, программа в потоке NTFS, конфигурация майнера, игровой чит, чит с конфигурацией майнера, подписанный `notepad.exe` как контроль), пара «майнер и сторож» и неопознанный сторож.

Для каждого проверяется по порядку: найдено; объяснено (серьёзность, улики, шаги, цепочка); обезврежено (объект действительно исчез, запись в карантине сделана); перепроверка внутри `--fix` согласна; восстановление из карантина возвращает то же самое (SHA-256 файлов, точное значение реестра, длина XML задачи); повторное появление после чистки распознаётся как «вернулось после очистки»; в конце система равна исходной (снимок реестра, служб, задач, WMI, автозагрузки) и ложных находок нет.

Результат: 198 пройдено, 0 не пройдено. Контроль (подписанный `notepad.exe`) не тронут. Игровой чит найден, помечен «оставлено» и не удалён; чит с конфигурацией майнера обезврежен вместе с программой и записью автозапуска. Сторож неизвестного вида: ответ честный (исход «частично», файл вернулся, «удалено» не заявлено).

**Слабые по замыслу (9 имитаций).** Одиночная запись автозапуска, которая указывает на неподписанную программу в пользовательской папке, находкой не становится: так делают обычные небольшие программы. Это значение Run, RunOnce, значение в `Policies\Explorer\Run`, регистрация COM-сервера, Active Setup, задача при входе с переменной в пути, обработчик выдуманного типа файлов, архив с файлом под именем майнера (заметка, 20 баллов) и скрытая системная программа в общей папке (заметка, 20 баллов). Они вместе с любой другой уликой дают находку (три способа автозапуска одной программы, содержимое файла, нагрузка, соединение с пулом). Набор записывает, что говорит MineHunter об этих имитациях, и не называет это успехом или провалом.

**42 «не проверялись»**: пять классов, которые нельзя создать безопасно на настоящем компьютере (Winlogon и ключи, ломающие запуск Windows, исключения Defender и hosts, повреждённая задача, внедрение в процесс, руткиты), и повторное появление после чистки, которое проверяется на представительном наборе (файлы, значения Run, задача, служба, WMI), а не на каждой имитации.
