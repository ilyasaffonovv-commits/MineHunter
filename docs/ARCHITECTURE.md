# Архитектура MineHunter

MineHunter — один исполняемый файл (.NET Framework 4.7.2 / WPF, x64, ~0,5 МБ), который входит в состав Windows 10/11 (устанавливать .NET не нужно). Никакого кода MinerSearch не использовано: конвейер, формат правил и модель оценки написаны заново.

```
 Scanner ──► Evidence ──► Analyzer ──► Risk ──► Decision ──► Remediation ──► Verification
 (собирает)  (улики)     (связи/граф)  (баллы)  (план)       (карантин)     (повторная проверка)
```

| Этап | Где в коде | Что делает |
|---|---|---|
| **Scanner** | `Scanning/*.cs` | Читает систему **только на чтение**: процессы и загруженные библиотеки, автозапуск (реестр, папки автозагрузки, службы/драйверы, задачи, WMI), вмешательство в защиту, браузеры, файлы. |
| **Evidence** | `Model/Model.cs`, `Scanning/FileIntel.cs` | Каждый сигнал — запись `Evidence(RuleId, Category, Weight, Text, Detail, Definitive)`, привязанная к объекту (`Entity`). Объекты связываются (`Link`). |
| **Analyzer** | `Risk/RiskEngine.cs` (`AddDerivedLinksAndEvidence`) | Строит граф, добавляет производные улики (несколько способов автозапуска одного файла, watchdog, CPU + автозапуск, копии файла). |
| **Risk** | `Risk/RiskEngine.cs` (`Compute`, `Decide`) | Прозрачный балл и вердикт с «корроборацией» — см. `RISK_MODEL.md`. |
| **Decision** | `Risk/RiskEngine.cs` (`Decision.Plan`) | Для каждой находки строит план шагов, что отключить/удалить, по умолчанию отмечены только шаги для «Высокий риск»/«Вредоносное». |
| **Remediation** | `Remediation/*.cs` | Обезвреживание «карантин-сначала»: остановка процессов, удаление автозапуска, перенос файлов в карантин; всё обратимо. |
| **Verification** | `Remediation/Verifier.cs` | Повторная проверка: находка считается устранённой, только если процесс не вернулся, файлы обезврежены и записи автозапуска исчезли. |

## Сканеры

* **ProcessScanner** — WMI + `GetProcessTimes`: список процессов, родитель, командная строка, CPU за 3 с (плюс GPU через счётчики `GPU Engine`), TCP-таблица по PID, DNS-кэш (для сопоставления соединения с доменом пула), проверка образа (`FileIntel`), загруженные модули (боковая загрузка DLL рядом с подписанным exe), **память**: заголовок образа в памяти против файла на диске (`PROC.HOLLOW.*`, подмена образа/process hollowing; только если файл не менялся с момента старта процесса), PE-образ в приватной исполняемой памяти (`PROC.PE_IN_PRIVATE_MEMORY`, ручная загрузка/внедрение), потоки, стартовавшие по адресу вне любого модуля (`PROC.ORPHAN_THREADS`, признак удалённого потока), полностью приостановленный LOLBIN (`PROC.SUSPENDED_LOLBIN`); число RWX-областей и объём исполняемой приватной памяти записываются в свойства процесса, но **сами по себе не оцениваются** (их создают JIT-компиляторы браузеров и .NET). Правила командной строки (`rules/core.json`) — пулы `stratum+tcp://`, кошелёк+алгоритм, отключение Defender и т. д.
* **PersistenceScanner** — `Run/RunOnce` (HKLM/HKCU/другие загруженные пользователи, WOW6432), Startup-папки (`.lnk` разбирается до цели), службы и драйверы (в т. ч. известные уязвимые драйверы, BYOVD), задачи планировщика (XML + `TaskCache\Tree`: скрытые задачи, `SD`/XML-несоответствия, подмена пространства `\Microsoft\…`), WMI-подписки (все классы потребителей), Winlogon (`Shell`/`Userinit`/`Notify`), IFEO/SilentProcessExit, AppInit_DLLs, LSA-пакеты, COM-hijack (`HKCU\Software\Classes\CLSID`), `Environment`-переменные (`COR_PROFILER` и т. п.), `BootExecute` и др.
* **TamperScanner** — исключения Защитника (пути/процессы/расширения; опасные — целый диск, `%TEMP%`, `AppData`), отключённая защита в реальном времени/политики, `DisallowRun`, файл hosts (блокировка сайтов антивирусов), правила брандмауэра, разрешающие недоверенные программы, прокси-настройки, команды отключения Defender в истории PowerShell, подмена `TermService`, а также состояние защиты (Defender/сторонний антивирус, UAC, SmartScreen, брандмауэр, обновления Windows) — оно показывается в блоке «Состояние системы» отдельными предупреждениями.
* **BrowserScanner** — профили Chrome/Edge/Brave/Opera/Yandex/Firefox: расширения (манифест + **код** `.js/.wasm/.html`), рискованные разрешения, подмена поисковика и стартовой страницы, «опасные» флаги запуска ярлыков.
* **FileSystemScanner** — уровни глубины: *Быстрая* (Temp, AppData, Downloads, Desktop, ProgramData, корни дисков, Windows\Temp и т. п.), *Полная* (все фиксированные диски, бюджет 45 минут), *Выборочная* (папка/диск на выбор). Постоянный кэш (`scancache.bin.gz`: путь + размер + время изменения → «доверенный»/«низкий риск»; кэш «низкого риска» сбрасывается при смене версии правил) делает повторные проходы в разы быстрее.
* **FileIntel** — единая «разведка по файлу»: подпись (WinVerifyTrust, файл + каталог Windows, без сетевой отзывности), класс доверия, разбор PE (секции, энтропия, импорты, оверлей, «раздутые» файлы), многошаблонный поиск строк майнеров (Ахо — Корасик, ASCII и UTF-16LE), маскировка (имя системной программы не в папке Windows, гомоглифы, «поддельные» сведения о версии), расположение, скрытые/системные атрибуты, инсталляторы и NGEN-образы (не подозрительны).

## Обезвреживание (карантин-сначала)

* Файл → `Quarantine/<id>/` (свой каталог и уникальный `id` на каждый объект, идентичные копии не перезаписывают друг друга). Содержимое хранится **не открытым текстом** (XOR со случайным 32-байтовым ключом на объект, чтобы файл нельзя было запустить и антивирус не сработал повторно); SHA-256 сверяется при записи и при восстановлении, повреждённая копия не восстанавливается.
* Задача планировщика/служба/значение реестра/WMI-подписка/исключение Защитника/hosts/расширение браузера: перед удалением экспортируется в JSON (реестр — вместе с подключами и типами значений), после удаления состояние проверяется. Восстановление создаёт объект заново.
* Занятые файлы: копия сохраняется, оригинал переименовывается и ставится на удаление при перезагрузке (`MoveFileEx`); GUI говорит «нужна перезагрузка».
* Порядок: сначала **заморозка** процессов (чтобы watchdog не воскресил), затем автозапуск, затем остановка процессов, затем файлы.
* Защита от самоповреждения: критические процессы (`csrss`, `lsass`, `wininit`, …) и доверенные/системные файлы не трогаются (`Decision.IsProtectedProcess/File`).

## Приватность и самозащита

* Ни файлы, ни хеши, ни журналы, ни имена машин никуда не отправляются; нет аккаунта и телеметрии. Единственный сетевой запрос — скачивание публичного `version.json` и пакета правил (см. `UPDATES.md`).
* Папка данных `%ProgramData%\MineHunter` (карантин, список «безопасное», правила, отчёты, конфиг) закрыта на запись для обычных пользователей — права выставляются при первом запуске от администратора.
* При запуске проверяется, не был ли предыдущий скан прерван (маркер `scan.lock`), и SHA-256 собственного exe до и после скана — вмешательство в сканер попадает в отчёт («Заметки о самозащите сканера»).
* Слепые зоны честно перечисляются в отчёте (процессы, к памяти которых нет доступа; папки, куда не пустили; скан прекращён по бюджету времени).
* Программа **не** отключает и не меняет настройки безопасности Windows.

## GUI

WPF без внешних библиотек. Разметка — `Gui/MainWindow.xaml` (вшита в exe и загружается при старте), поведение — `Gui/MainWindow.cs`, граф угрозы — `Gui/GraphView.cs`. Тёмная тема, RU/EN (`Report/Loc*.cs`). Все длительные операции идут в фоне; закрытие окна во время обезвреживания блокируется. Для автоматических проверок интерфейса есть скрытые ключи `--shot/--shots` (скриншот окна после скана) и `--neutralize <текст>` (обезвредить только находки, содержащие текст, — для лабораторных тестов).

## Командная строка

`MineHunter.exe scan --quick|--full|--path <папка> [--fix --yes --min suspicious|high|malware --only <текст> --all-steps] [--report-dir <папка>] [--json <файл>] [--dump <файл>] [--no-browsers --no-memory --no-files --no-cache] [--quiet]`, `quarantine list|restore <id>|delete <id>|delete-all`, `allow <путь>`, `update-check`, `update-rules`, `rules-info`, `markers <файл>`, `selftest`, `--gen-signing-keys`, `--sign`. Коды выхода: 0 — чисто, 1 — подозрительное, 2 — высокий риск/вредоносное, 3 — ошибка, 4 — нужно подтверждение (`--yes`). `MineHunter.exe` собран как оконное приложение; для скриптов рядом лежит `MineHunter-cli.exe` (тот же код, консольный режим) — он дожидается завершения и пишет в stdout.

## Что программа НЕ делает (границы)

* Это **эвристический** охотник за майнерами и закреплением, а не полноценный антивирус: нет драйвера режима ядра, нет проверки трафика в реальном времени, нет облачных репутаций. Руткиты уровня ядра и зашифрованные/упакованные образцы, ничем не выдающие себя на диске, в памяти и в автозапуске, могут остаться незамеченными.
* Постоянного «щита» нет: проверка по запросу. Для постоянной защиты нужен обычный антивирус — при его отсутствии программа сообщает об этом в блоке «Состояние системы».
* Полная проверка ограничена бюджетом времени (45 мин); недосмотренное перечисляется в отчёте, повторный запуск быстрее благодаря кэшу.
