# Архитектура

.NET Framework 4.7.2, x64, WPF, без сторонних пакетов. Отдельно ставить .NET не нужно, он входит в Windows 10/11.

## Состав решения

Движок один, оболочек несколько. Все четыре программы подключают одну и ту же сборку `MineHunter.Core.dll`, поэтому одна и та же проверка даёт один и тот же результат в любой из них (это проверяет самотест: движок и общий запускатель дают одинаковые находки для одинаковых параметров).

```
src/
  MineHunter.Core         движок: сканеры, оценка риска, обезвреживание, правила, обновление, отчёты, защита в реальном времени,
                          настройки, расписание, драйверы, здоровье Windows, анализ файла, самотест, команды консоли
  MineHunter.UI           окна: главное окно с 13 страницами, окно проверки, трей, всплывающее предупреждение (WPF, разметка в коде)
  MineHunter              MineHunter.exe          главная программа (окно, трей, плановая проверка, команды Проводника, консольные команды)
  MineHunter.QuickScan    MineHunter Quick Scan.exe   двойной щелчок = быстрая проверка с живым состоянием
  MineHunter.FullScan     MineHunter Full Scan.exe    двойной щелчок = полная проверка всех дисков
  MineHunter.Cli          MineHunter-cli.exe      настоящая консольная программа для скриптов
  MineHunter.UpdateHelper components\MineHunter.UpdateHelper.exe   ставит проверенное обновление, не зависит от остального кода
```

Портативная папка (после `build_release.ps1`, она же содержимое zip):

```
MineHunter.exe  MineHunter Quick Scan.exe  MineHunter Full Scan.exe  MineHunter-cli.exe  (+ .config)
components\     MineHunter.Core.dll  MineHunter.UI.dll  MineHunter.UpdateHelper.exe     служебные файлы
rules\  config.json  docs\  README*.md  LICENSE  SHA256SUMS.txt
```

Служебные библиотеки лежат в `components\`: `app.config` каждой программы содержит `<probing privatePath="components"/>`, поэтому рядом с программами остаются только четыре exe. Если библиотеки лежат рядом с exe (так собирается решение при разработке), всё работает так же. Если программу запустили без `components\` (например, из окна архива или скопировав один exe), `src/LaunchGuard.cs` (общий файл всех четырёх программ) перехватывает ошибку «не найден MineHunter.*» и показывает одну понятную фразу на русском и английском вместо окна сбоя .NET; консольная версия пишет её в stderr и возвращает код 3.

### Что общее для всех программ

| Часть | Файл | Зачем |
|---|---|---|
| Запуск | `App/Bootstrap.cs` | Журнал сбоев, загрузка настроек и языка, закрытие папки данных для обычных пользователей, возврат замороженных процессов после оборванной очистки. |
| Параметры проверки | `Scanning/ScanProfiles.cs` | Единственное место, где «быстрая / полная / выборочная» и настройки превращаются в параметры движка. Её вызывают окна, обе программы проверки, плановая проверка и консоль. |
| Запуск проверки | `Scanning/ScanRunner.cs`, `ScanController.cs` | Движок, затем отчёты (txt, json, html), запись в историю, снимок результата для другого окна. Одна проверка за раз на весь компьютер (замок-файл). |
| Живое состояние | `Scanning/ScanContext.cs` (`ScanProgress`) | Что проверяется сейчас, сколько объектов, сколько прошло времени, сколько подозрительного уже набралось. Окна читают это раз в 0,4 с. |
| Настройки | `App/Settings.cs` | `settings.json` в защищённой папке данных. Неизвестные значения возвращаются к безопасным. |
| История и журнал | `App/History.cs`, `Guards/GuardModel.cs` (`SystemJournal`) | Прошлые проверки и изменения в системе. |
| Снимок последней проверки | `Report/ResultSnapshot.cs` | Находки целиком (объекты, улики, связи, шаги): так окно проверки «открывает в основной программе» то же самое и позволяет обезвредить. |

Исправление есть только там, где оно безопасно, и выполняется по клику. |

| Контекстное меню | `App/ShellIntegration.cs` | Записи в HKCU, без прав администратора, убираются без следа. |

## Конвейер

```
Scanner -> Evidence -> Analyzer -> Risk -> Decision -> Remediation -> Verification
```

| Этап | Где в коде | Что делает |
|---|---|---|
| Scanner | `Scanning/*.cs` | Только читает систему: процессы и модули, автозапуск, вмешательство в защиту, браузеры, файлы. |
| Evidence | `Model/Model.cs`, `Scanning/FileIntel.cs` | Каждый признак это `Evidence(RuleId, Category, Weight, Text, Detail, Definitive)`, привязанный к объекту (`Entity`). Объекты связываются через `Link`. |
| Analyzer | `Risk/RiskEngine.cs`, `AddDerivedLinksAndEvidence` | Строит граф и добавляет производные улики (несколько способов автозапуска у одного файла, watchdog, копии файла). |
| Risk | `Risk/RiskEngine.cs`, `Compute` и `Decide` | Считает балл и вердикт, см. [RISK_MODEL.md](RISK_MODEL.md). |
| Decision | `Risk/RiskEngine.cs`, `Decision.Plan` | Строит для находки список шагов. По умолчанию отмечены шаги только для «Высокого риска» и «Вредоносного». |
| Remediation | `Remediation/*.cs` | Выполняет шаги: заморозка процессов, удаление автозапуска, остановка процессов, перенос файлов в карантин. |
| Verification | `Remediation/Verifier.cs` | Повторная проверка. Находка считается устранённой, если процесс не вернулся, файлы обезврежены, записи автозапуска исчезли. |

Порядок работы `ScanEngine`: процессы, затем автозапуск (реестр, папки автозагрузки, службы, задачи, WMI параллельно), затем защита Windows, браузеры, файлы, анализ связей. На время проверки процесс работает с приоритетом `BelowNormal`.

## Сканеры

`ProcessScanner`. Список процессов через WMI и `GetProcessTimes`, родитель, командная строка. Загрузка CPU считается за окно 3 с, загрузка GPU берётся из счётчиков «GPU Engine» (если счётчиков нет, GPU не учитывается). TCP-таблица по PID, DNS-кэш для сопоставления соединения с доменом пула. Загруженные модули для поиска подмены DLL. Память (если не отключена в настройках): заголовок образа в памяти сравнивается с файлом на диске (`PROC.HOLLOW.*`, только если файл не менялся после старта процесса), PE-образы в приватной исполняемой памяти (`PROC.PE_IN_PRIVATE_MEMORY`), потоки, стартовавшие вне модулей (`PROC.ORPHAN_THREADS`), приостановленные системные утилиты (`PROC.SUSPENDED_LOLBIN`). Число RWX-областей и объём исполняемой приватной памяти записываются в свойства процесса, но сами не оцениваются: их создают JIT-компиляторы браузеров и .NET. К памяти защищённых процессов доступа нет, такие процессы попадают в список слепых зон отчёта.

Автозапуск, файл `Scanning/PersistenceScanner.cs`:
- `RegistryPersistenceScanner`: Run и RunOnce (HKLM, HKCU и загруженные профили других пользователей, WOW6432), Winlogon, IFEO и SilentProcessExit, AppInit_DLLs, AppCertDLLs, пакеты LSA, COM-регистрации в HKCU, переменные окружения профилировщика, BootExecute.
- `StartupScanner`: папки автозагрузки, `.lnk` разбирается до цели.
- `ServiceScanner`: службы и драйверы, включая известные уязвимые драйверы по списку имён в правилах.
- `TaskScanner`: задачи планировщика по XML и по `TaskCache\Tree` (скрытые задачи, расхождения XML и дескриптора `SD`, задачи под `\Microsoft\`). Действия `ComHandler` (бесфайловая задача, запускающая COM-класс вместо программы) разбираются отдельно: class id ищется в HKCU, затем в HKLM, как это делает сама COM-подсистема; реализация, найденная только в HKCU, отдельная улика (`TASK.COMHANDLER_HKCU`), задача при этом связывается с её COM-записью в реестре в одну находку.
- `WmiScanner`: все классы потребителей событий, фильтры и привязки.

`TamperScanner`. Исключения Защитника (пути, процессы, расширения; локальные и из политик), отключённая защита в реальном времени, `DisallowRun` и запрет системных инструментов, hosts, правила брандмауэра для программ из пользовательских папок, команды отключения Defender в истории PowerShell, подмена `TermService`. Состояние защиты (Defender или сторонний антивирус, UAC, SmartScreen, брандмауэр, обновления Windows) показывается в блоке состояния системы отдельными предупреждениями.

`BrowserScanner`. Профили Chrome, Edge, Brave, Opera, Opera GX, Яндекса, Vivaldi, Avast Secure Browser, Chromium и Firefox: манифест и код расширений (`.js`, `.wasm`, `.html`), разрешения, расширения, установленные политикой, подмена поиска и стартовой страницы, ярлыки с опасными параметрами. Отдельно проверяются расширения VS Code, Cursor и Windsurf.

`FileSystemScanner`. Быстрая проверка обходит типичные места подброса (Temp, AppData, Downloads, Desktop, ProgramData, корни дисков, Windows\Temp и т. п.), полная все фиксированные диски (лимит по умолчанию 45 минут), выборочная папку или диск. Кэш `scancache.bin.gz` хранит путь, размер и время изменения файлов, признанных безобидными; он сбрасывается при смене версии правил или движка.

`FileIntel`. Сведения о файле: подпись (WinVerifyTrust по файлу и каталогу Windows, без проверки отзыва по сети), класс доверия, разбор PE (секции, энтропия, импорты, оверлей, раздутые файлы), поиск строк майнеров (Ахо-Корасик, ASCII и UTF-16LE), маскировка (системное имя не в папке Windows, гомоглифы, поддельные сведения о версии), расположение, атрибуты, признаки установщиков и NGEN-образов.

## Обезвреживание

- Файл попадает в `Quarantine/<id>/`, где для каждого объекта свой каталог и уникальный id. Содержимое маскируется XOR со случайным ключом на 32 байта, чтобы файл нельзя было запустить и антивирус не срабатывал повторно. SHA-256 сверяется при записи и при восстановлении, повреждённая копия не восстанавливается.
- Задача, служба, значение реестра, WMI-подписка, исключение Защитника, hosts и расширение браузера перед удалением сохраняются (реестр вместе с подключами и типами значений), после удаления состояние проверяется. Восстановление создаёт объект заново. Правила брандмауэра только записываются и автоматически не восстанавливаются.
- Занятый файл переименовывается и ставится на удаление при перезагрузке (`MoveFileEx`).
- Порядок: заморозка процессов (чтобы watchdog не перезапустил удалённое), автозапуск, остановка процессов, файлы.
- Критические процессы (`csrss`, `lsass`, `wininit` и другие) и доверенные системные файлы не трогаются (`Decision.IsProtectedProcess` и `IsProtectedFile`).

## Данные и самопроверка

- Папка `%ProgramData%\MineHunter` (карантин, список исключений, правила, конфигурация) закрывается на запись для обычных пользователей при первом запуске от администратора. Отчёты в этот список не входят: в них нет ничего, что нужно защищать, поэтому они пишутся в папку `Reports` рядом с exe (`Report/ReportWriter.cs`, `DefaultDir`), чтобы их было видно сразу. Если эта папка недоступна для записи, отчёты падают обратно в `%ProgramData%\MineHunter\Reports`.
- При запуске проверяется маркер `scan.lock`: если прошлая проверка оборвалась, это попадает в отчёт. SHA-256 собственного exe записывается до и после проверки.
- Слепые зоны (процессы без доступа к памяти, недоступные папки, остановка по лимиту времени) перечисляются в отчёте.

## Окна

WPF без внешних библиотек, страницы строятся в коде из небольшого набора помощников (`Ui.cs`), стили и цвета лежат в `Theme.xaml`, вшитом в сборку. Страницы: Главная, Проверка, Защита, Проверка файла, Процессы, Автозапуск, Сеть, Карантин, Драйверы, Здоровье Windows, Расписание, История, Настройки. Окно проверки (`ScanPanel`) одно и то же в главной программе и в Quick Scan / Full Scan. Граф связей находки: `GraphView.cs`. Строки RU и EN: `Loc.L(en, ru)` в коде и `Report/Loc*.cs` для движка. Долгие операции выполняются в фоне. Служебные ключи для снимков экрана и проверок интерфейса: `--shots <папка>`, `--shot <файл> --page <страница>`, `--lang ru|en`, `--page alert` (всплывающее предупреждение).

Ключи главной программы: `--tray` (только значок), `--scheduled quick|full|custom` (плановая проверка без окна), `--open-last` (последний результат), `--check-file`, `--analyze-file`, `--scan-folder` (из меню Проводника; принимается только один существующий файл или папка), `--page <имя>`. Вторая копия передаёт команду уже запущенной через именованный канал, доступный только текущему пользователю.

## Командная строка

Справка: `MineHunter-cli.exe --help`. Это настоящая консольная программа (отдельный проект `MineHunter.Cli`), для скриптов и ssh. `MineHunter.exe` с консольными командами тоже работает (подключается к консоли родителя). Кроме `scan`, `quarantine`, `allow`, `update-check`, `update-rules`, `rules-info`, `markers`, `selftest`: `quick`, `full`, `check <файл>`, `hash`, `reputation <sha256>`, `status`, `health`, `processes`, `connections`, `startup`, `drivers`, `history`, а `scan <файл>` проверяет один файл. Коды выхода: 0 чисто, 1 подозрительное, 2 высокий риск или вредоносное, 3 ошибка, 4 нужно подтверждение.

## Чего программа не делает

- Нет драйвера режима ядра и разбора пакетов. Защита в реальном времени работает в пользовательском режиме (наблюдает и сообщает, до запуска не блокирует). Руткиты уровня ядра и образцы, не оставляющие следов на диске, в памяти и в автозапуске, могут остаться незамеченными.
- Облачной репутации MineHunter нет (сервера не существует). VirusTotal по хешу можно включить вручную, по умолчанию он выключен.
- Если рабочего антивируса в системе нет, программа сообщает об этом, но антивирусом не становится.
- Полная проверка может быть ограничена по времени (настройка). То, что не успели просмотреть, перечисляется в отчёте.
