# Обновления MineHunter (как это работает и как выпускать новые версии)

## Что видит пользователь

Пользователь дважды кликает `MineHunter.exe`. Программа **сразу**:

1. показывает в правом верхнем углу «плашку версии»: `✓ Версия 1.0.0 — последняя`, `⬆ Доступна версия 1.1.0 — скачать`, `○ Нет сети — проверка пропущена` или `ⓘ Источник обновлений ещё не задан`;
2. если есть новые **правила детекта** — скачивает их, проверяет (SHA-256 и, если настроено, подпись RSA) и подключает сама;
3. запускает быструю проверку (можно отключить в «О программе → Настройки»).

Плашка «Доступна версия…» открывает страницу релиза на GitHub — пользователь скачивает новый `MineHunter.zip` как обычный файл. Самой программой `.exe` подменять себя **не умеет** (это сознательно: самообновляющийся антивирус — лишняя поверхность атаки; для «простых людей» скачать zip с GitHub достаточно).

## Приватность обновлений

Единственный сетевой запрос — обычный HTTPS-`GET` публичного файла `version.json` (и, если есть, файла с правилами). Никаких идентификаторов, хешей, путей, имён файлов или журналов **не отправляется**. Без сети программа работает полностью (проверка идёт локально).

## Формат `version.json`

Положите в репозиторий GitHub (например, в корень ветки `main`) и укажите его «raw»-адрес в `config.json` (`updateManifestUrl`):

```json
{
  "latestVersion": "1.1.0",
  "releaseUrl": "https://github.com/<владелец>/MineHunter/releases/latest",
  "notes": "Что нового",
  "rules": {
    "version": "2026.10.01.1",
    "url": "https://raw.githubusercontent.com/<владелец>/MineHunter/main/rules/core.json",
    "sha256": "<SHA-256 файла правил, 64 hex-символа>",
    "signature": "<подпись RSA-SHA256 в Base64; нужна, если задан updatePublicKeyXml>"
  }
}
```

Готовый шаблон лежит в `version.json` в корне папки проекта.

## Как выпустить новую версию программы

1. В `src/MineHunter/MineHunter.csproj` и `Scanning/ScanEngine.cs` (`AppInfo.Version`) поднимите номер.
2. Соберите: `dotnet build -c Release -o ..\_bin` (или запустите GitHub Actions, см. `.github/workflows/build.yml`).
3. Упакуйте `MineHunter.exe` + `rules\` + `config.json` + `README.md` в zip, создайте на GitHub **Release**, приложите zip.
4. Поменяйте `latestVersion` в `version.json` — у всех пользователей загорится «Доступна новая версия».

## Как выпустить новые правила (чаще, чем программу)

Правила — обычный JSON (`rules/core.json`): строки майнеров, шаблоны командных строк, домены пулов, списки доверенных издателей и «тяжёлых» программ, известные вредоносные пути. Хеши известного вредоносного ПО добавляются в тот же JSON-пакет объектом `"badHashes": { "<sha256>": "название семейства" }` или локально файлами `hashes*.txt` рядом с программой (строка: `sha256 имя`, `#` — комментарий). **Только из проверенных источников**: в комплект списки хешей не входят, выдумывать их нельзя — совпадение с таким хешем даёт 100 баллов («Вредоносное»).

1. Отредактируйте `rules/core.json`, поднимите `version` (формат `ГГГГ.ММ.ДД.N`, сравнивается как строка).
2. Посчитайте SHA-256: `Get-FileHash rules\core.json -Algorithm SHA256`.
3. (Рекомендуется) подпишите: `MineHunter.exe --sign rules\core.json update_private.xml` — команда печатает подпись в Base64.
4. Внесите `version`, `sha256`, `signature` в `version.json`, закоммитьте.

### Подпись правил (защита от подмены)

Правила могут расширять список доверенных издателей — значит, поддельный набор правил мог бы «выпустить» вредоносную программу из-под проверки. Поэтому:

* один раз создайте пару ключей: `MineHunter.exe --gen-signing-keys .\keys` → `update_private.xml` (**секретный, не публиковать и не терять**) и `update_public.xml`;
* содержимое `update_public.xml` вставьте в `config.json` → `updatePublicKeyXml`;
* с этого момента программа принимает только пакеты с верной подписью. Без ключа проверяется лишь SHA-256 — это защищает от повреждения файла, но **не** от компрометации репозитория.

Программа отклоняет пакет, если: адрес не HTTPS (исключение — loopback для тестов), размер > 8 МБ, SHA-256 не совпал или не указан, подпись неверна/отсутствует при заданном ключе, файл не разбирается как правила или в нём нет версии. Всё это проверено автоматически (`MineHunter.exe selftest`, раздел «Update flow end-to-end» — поднимается локальный сервер и проверяются все ветки, включая подмену).

## Куда ложатся скачанные правила

`%ProgramData%\MineHunter\rules\update-*.json`. Папка данных доступна на запись только администраторам (программа выставляет права при первом запуске), поэтому обычная программа не может подложить туда своё «правило». Наборы правил объединяются: вшитые в exe + папка `rules\` рядом с программой + скачанные обновления. Списки пополняются (ничего не пропадает), правила командной строки с одинаковым `id` не дублируются, а «версия набора» — наибольшая из найденных.

## Известное ограничение

Пока `updateManifestUrl` пуст, программа честно пишет «источник обновлений ещё не задан». Адрес появится, когда вы создадите репозиторий на GitHub: впишите его в `config.json` (или в `AppConfig.DefaultManifestUrl` перед сборкой, чтобы он был вшит).
