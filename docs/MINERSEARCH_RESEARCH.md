# MinerSearch v1.4.9.4: результаты разбора

Разбор проводился на компьютере с Windows 11 25H2 x64 с правами администратора. Пометка «код» означает чтение исходников `BlendLog/MinerSearch` тега `v1.4.9.4` (коммит `26f53c7`), «запуск» означает наблюдение за фактической работой. Снимки системы, трассы ETW и журналы в репозиторий не входят.

## 1. Архив и сборка

| Проверка | Результат |
|---|---|
| Файлы в архиве | `MinerSearch_v1.4.9.4.exe` (669 184 байта), `dbase.dll`, `netlib.dll`, `Win32Wrapper.dll`, EULA, справка |
| Подпись Authenticode | Нет (`NotSigned`), все файлы не подписаны |
| SHA-256 exe | `569c8821…d5edc759`, совпал с `hashes.txt` из архива |
| Платформа | .NET Framework 4.8, WinForms и консоль, AnyCPU, манифест `requireAdministrator` |
| Сборка из исходников | Удалась (MSBuild из VS 2026; пакета таргетинга 4.8 не было, поэтому собрано с `TargetFrameworkVersion=v4.7.2`) |
| Сравнение с архивом | Для 205 типов и 2252 методов exe и всех методов трёх DLL IL совпадает побайтно. Различаются метаданные (MVID, метки времени, ресурсы). Архив соответствует исходникам тега. |

## 2. Устройство (код)

Цепочка `Scanner`, `Analyzer`, `ThreatDecision`, `CleanManager`. Порядок в `Program.ExecuteScanWorkflow`:

1. `RootkitScanner` (только r77 и только собственный процесс, см. раздел 5).
2. Процессы, анализ, фаза SuspendOnly (процесс замораживается, файлу закрывается запуск через ACL).
3. Остальное: файлы, автозагрузка, реестр, службы, задачи, брандмауэр, WMI, hosts, профили браузеров, затем фаза DisableExecuteOnly.
4. Сигнатурный поиск `*.exe` в пяти корнях.
5. Известные угрозы применяются сразу, неизвестные попадают в окно проверки или (при `autoacceptunknown=1` в реестре) принимаются автоматически.
6. Finalize: завершение процессов, карантин или удаление файлов, реестр, службы.

Проверки или повторного скана после лечения нет.

Детект опирается на зашитые списки IOC (около 1000 записей: пути, имена файлов, аргументы, ветки реестра, строки, зашифрованные AES через `Bfs.Create`) для конкретных семейств (`ReaItekHD`, `WindowsTask`, `taskhost.exe` в ProgramData, `RDPWinst.exe`, TektonIT и RMS, `DisallowRun`, задачи в `\Microsoft\Windows\WindowsBackup\`) и на узкие общие эвристики.

## 3. Поведение при запуске

- Запуск `-so -cm` на тестовом компьютере: 0 угроз.
- Изменения в системе при режиме scan-only: значение `HKLM\SOFTWARE\M1nerSearch\runcount` (+1 за запуск) и журнал в `C:\_MinerSearchLogs`. Других файлов, задач, служб и веток реестра он не менял.
- Сеть (ETW Kernel-Network, PID процесса): одно соединение `193.23.197.229:443` через секунду после старта, 0,6 с, около 1 КБ вверх и 5,6 КБ вниз, это проверка обновлений. Отправка лога на сервер возможна из окна результатов (`FinishEx.SendLogAndHandleErrors`) при `allowstatistics=1`, в консольном режиме этого пути нет.
- Процесс: приоритет `RealTime`, пик около 1 ГБ ОЗУ, 131–160 с процессорного времени, 31,6 ГБ прочитано с диска за проход (2,5–3,5 мин), дочерних процессов нет.
- Привилегии токена: `SeDebugPrivilege` и `SeBackupPrivilege` включены в режиме scan-only, остальные выключены.
- При перенаправленном stdout падает (`Console.BufferWidth` и `GetBufferInfo` дают `IOException`). Родителя PowerShell распознаёт только по имени `powershell`, а не `pwsh`. На неверный аргумент вызывает `Console.ReadKey` и падает при перенаправленном вводе.

По журналам прежних запусков на другом тестовом компьютере с настоящим заражением одного семейства (набор `WindowsTask`, `ReaItekHD`, `winserv`, `RDPWinst`, RMS, `DisallowRun`, задачи `WindowsBackup`, исключения Defender, всё это IOC из кода MinerSearch) он находил и лечил десятки объектов. Там же несколько запусков подряд показывали одни и те же три угрозы (исключения Defender для `%TEMP%`, `C:\ProgramData`, `*.exe`): что-то возвращало их между запусками. При `autoacceptunknown=1` он без вопроса удалил значение IFEO `GlobalFlag` (512) у exe одной игры, то есть настройку, которую могло выставить само приложение.

## 4. Лаборатория: результат MinerSearch в режиме scan-only

Объекты создаёт `tests/MinerLab`. Всё помечено `MinerLabTest`, после тестов удаляется `MinerLabCleanup.ps1`, возврат к исходному состоянию подтверждён сравнением снимков.

| Сценарий | Результат MinerSearch |
|---|---|
| Командная строка как у майнера (`--algo`, `stratum+tcp://`, `--pass x`, порт 3333) | Обнаружено: «Malicious process», риск high (5) |
| `svchost.exe` и `taskhostw.exe` в Temp или AppData, не подписаны | Обнаружено, риск middle (3) |
| Неподписанный exe в корне `%APPDATA%` или `%LOCALAPPDATA%` | Обнаружено (`Unsigned executable in system location`) |
| Служба с именем exe и образом в Temp | Обнаружено («Suspicious service image») |
| Неподписанный exe в подпапках Temp и AppData, в Program Files, в ProgramData | Не помечено, только `[!] No signature` |
| CPU 80 %, ОЗУ 800 МБ, loopback-сокет :3333 | Не помечено |
| Цепочка Launcher, Sim, Worker | Не связывается |
| Run (HKCU и HKLM), неподписанный exe | Запись `[.] File:` в журнале, вердикта нет |
| Задачи (обычная, скрытая, в `\Microsoft\Windows\…`, с повтором) | Сканируются, `[OK]` |
| WMI CommandLine без `cmd.exe /c` и `..\`, ActiveScript | Не помечено. В коде смотрится только `CommandLineEventConsumer` и только по `..\` или `cmd.exe /c `, фильтры, привязки и остальные потребители игнорируются |
| Ярлык автозагрузки, неподписанный exe | Только журнал |
| Объект с несколькими сигналами (неподписанный, AppData, CPU 60 %, Run, задача, ярлык, цепочка, сокет) | Не помечен, комбинация сигналов уверенность не повышает |
| Копия `notepad.exe` с подписью Microsoft в Temp | Ложных срабатываний нет |

## 5. Проверка руткитов

Проверяется только семейство r77 (bytecode77) и только собственный процесс: читаются заголовки собственных модулей, в DOS-заголовке ищутся три сигнатуры, при находке выполняется отсоединение через `NtCreateThreadEx`. В режиме `--scan-only` проверка принудительно отключена (`no_rootkit_check = true`). Не видит драйверные руткиты, буткиты, DKOM, скрытые процессы и другие семейства. На живом образце не проверялось (нужен настоящий r77), вывод сделан по коду.

## 6. Лечение

Порядок по журналу без `-so`, только на тестовых объектах: обнаружение, заморозка 3 процессов (примерно через 30 с после старта), сканы, «Threats processing» (завершение процессов, карантин или удаление файлов, удаление службы). Проверки результата и повторного скана нет.

На 6 помеченных объектах:
- обработаны 3 процесса (завершены), 2 файла (в карантин), 1 служба (удалена без карантина);
- не обработаны, хотя помечены: файлы `taskhostw.exe`, `MinerLabTest_root.exe` и exe процесса с командной строкой майнера остались на диске. Сводка при этом писала «Total cured threats: 5 of 5».

Причина по коду и запуску: `FileThreatObject.Id` это хеш содержимого, `ExecuteScanWorkflow` отбрасывает решения с уже обработанным `Id`, а карантин хранится в `HKLM\SOFTWARE\M1nerSearch\Quarantine\<MD5>`, поэтому одинаковые копии перезаписываются или пропускаются.

Карантин: файл режется на блоки по 512 КБ в бинарные значения реестра `FileData_PartN` (плюс `OriginalPath`, `QuarantinedAt`), задачи, службы и ветки реестра имеют отдельные типы. SHA-256 и проверки целостности при восстановлении нет, для WMI, брандмауэра, hosts и удалённых служб карантина нет. Восстановление (`-q -cm -res= 1 -f`) работает, файл вернулся с тем же SHA-256, но второй файл, помещённый в карантин, восстановить нельзя: его запись перезаписана записью с тем же MD5.

## 7. Итоги разбора

Подтверждено: MinerSearch чистит известные семейства по IOC, умеет работать из-под WinPE, имеет консольный режим и снимает ACL с объектов, защищённых вредоносной программой.

Слабые места, найденные при разборе: зависимость от IOC и мало общих эвристик, нет объединения улик, WMI, автозагрузка и ярлыки почти не оцениваются, приоритет `RealTime` и 31 ГБ чтения, нет повторной проверки после лечения, карантин с коллизиями и без хеша, автоудаление по одиночной эвристике (пример: IFEO `GlobalFlag`), служба удаляется без карантина, падение при перенаправлении вывода, отправка логов автору при включённой статистике.

Источники по актуальным семействам, использованные при составлении правил MineHunter, перечислены в [THREAT_RESEARCH.md](THREAT_RESEARCH.md).
