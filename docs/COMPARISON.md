# MineHunter против MinerSearch v1.4.9.4 — сравнение на одном и том же состоянии системы

Всё ниже измерено на этой машине (Windows 11 25H2 x64, 24 логических ядра, права администратора). MinerSearch запускался в режиме `-so -cm -v` (только отчёт, без лечения), MineHunter — `scan --quick`. Исходная лаборатория — безвредная имитация заражения `tests/MinerLab` (каждый объект помечен `MinerLabTest`, все копии «майнера» — разные файлы с разными хешами, как у несвязанных программ). Сырые логи обеих программ — в `research/`. Подробности о самом MinerSearch — `docs/MINERSEARCH_RESEARCH.md`.

## 1. Лаборатория: что нашла каждая программа

| Сценарий | MinerSearch | MineHunter |
|---|---|---|
| Процесс с командной строкой майнера (пул, пользователь, алгоритм) | обнаружен, риск 5 («high») | **Высокий риск 84** (полная командная строка — решающая улика) |
| Запущенный `svchost.exe` из `%TEMP%` | обнаружен, риск 3 | **Высокий риск 76** (маскировка + «работает прямо сейчас») |
| Запущенный `taskhostw.exe` из `%APPDATA%` | обнаружен, риск 3 | **Высокий риск 67** |
| `csrss.exe` и `RuntimeBroker.exe` под системными именами, но **не запущены** | только «нет подписи» | `csrss.exe` — часть высокого риска (лежит рядом с запущенным поддельным `svchost.exe`), `RuntimeBroker.exe` — **Подозрительное 41** |
| Неподписанный exe **в корне** `%APPDATA%` / `%LOCALAPPDATA%` | предупреждение `[!!]` | заметка (18) — **не угроза** |
| Служба: имя = имя exe, образ в `%TEMP%` | обнаружено («Suspicious service image») | **Высокий риск 70**: вся связка (служба + скрытая задача + ярлык автозагрузки + файлы) как одна находка |
| Служба с образом в `%LOCALAPPDATA%` | не помечено | Подозрительное |
| **Скрытая** задача планировщика → exe в Temp | сканируется, без вердикта | входит в высокий риск (TASK.HIDDEN + путь) |
| Задача в `\Microsoft\Windows\…` → неподписанный exe в AppData | без вердикта | **Подозрительное 50** (`TASK.MS_NAMESPACE_UNTRUSTED`) |
| Автозапуск Run (HKCU) → неподписанный exe | только запись в лог | Подозрительное (в связке) |
| Автозапуск Run (HKLM) → неподписанный exe в Program Files | только лог | 3 балла — **ничего** (это нормальная ситуация) |
| **WMI**: `CommandLineEventConsumer` с обычным путём | **слепая зона** (ищет только `..\` и `cmd.exe /c`) | Подозрительное 54 (`WMI.CMDLINE_CONSUMER`, в связке с Run и службой) |
| **WMI**: `ActiveScriptEventConsumer` | **слепая зона** | **Подозрительное 30** (`WMI.SCRIPT_CONSUMER`) |
| Ярлык автозагрузки → exe в Temp | только лог | входит в высокий риск |
| Мульти-сигнальный объект (неподписанный + AppData + Run + задача с повтором + ярлык + watchdog-цепочка) | **не помечен вообще** | **Подозрительное 57**, все звенья в одной находке с объяснением |
| Высокая загрузка CPU / 800 МБ ОЗУ / loopback-сокет :3333 сами по себе | не помечено | не помечено (**так и задумано** — слабые сигналы не осуждают программу) |
| Копия `notepad.exe` (подпись Microsoft) в Temp | не помечено | не помечено |
| Цепочка Launcher → Sim → Worker без других улик | не связывается | не помечается; связывается в граф, когда есть повод |
| **Сам сканер-антимайнер** (`MineHunter.exe`) | **помечен как «Malicious file»** (ложное срабатывание: в exe открытым текстом лежал список майнерских строк) | не помечается (правила внутри exe сжаты и замаскированы — проверено MinerSearch как «оракулом» на релизных `MineHunter.exe`/`MineHunter-cli.exe`) |

Итог MinerSearch на этой лаборатории (его собственная сводка): **11 угроз, 2 подозрительных**, 4 мин 29 с. В журнале отмечены `[!!!]`: процесс с командной строкой майнера, два «системных» процесса, служба с образом в Temp и **два экземпляра `MineHunter.exe`** (ложное срабатывание на нашу же программу); как именно набралось «11» в сводке, журнал не расшифровывает. Замеры нагрузки MinerSearch (приоритет `RealTime`, ≈ 31 ГБ чтения за проход) — в `MINERSEARCH_RESEARCH.md`.
MineHunter: **6 высокого риска, 5 подозрительных, 25 мелких заметок** (два из шести «высокого риска» — реальные остатки старого заражения, см. ниже), Быстрая проверка 50–110 с, приоритет `BelowNormal`.

## 3. Архитектурные различия

| | MinerSearch | MineHunter |
|---|---|---|
| Основа детекта | зашитые списки IOC (пути/имена/аргументы конкретных кампаний) + узкие эвристики | прозрачные улики по категориям + корроборация независимых сигналов; правила — в открытом JSON |
| Итоговое решение | суммирование целых баллов, порог 3 | балл с потолками категорий, вердикт только при совпадении нескольких видов улик, объяснение «почему не выше» |
| Связь объектов | нет (дедупликация по хешу содержимого, которая **теряет одинаковые копии**) | граф угрозы: автозапуск → файл → процесс → сеть; одна находка = вся связка |
| WMI | только `CommandLineEventConsumer` с `..\`/`cmd.exe /c` | все классы потребителей, фильтры, привязки |
| Память | нет (rootkit-проверка — только r77 и только собственный процесс, в `-so` отключена) | подмена образа, PE в приватной памяти, потоки вне модулей, приостановленный LOLBIN |
| Сеть ↔ процесс | нет | соединения по PID, порты майнинга, домены пулов по DNS-кэшу |
| Карантин | файл режется на блоки по 512 КБ в реестр `HKLM`, ключ = MD5 → **одинаковые копии перезаписывают друг друга**; нет SHA-256 | папка на каждый объект, уникальный id, XOR-маскировка, SHA-256 при записи и восстановлении; задачи/службы/реестр/WMI/hosts/расширения — в JSON |
| После лечения | повторной проверки нет | автоматический повторный скан; «устранено» только если скан подтверждает |
| Занятые файлы | — | переименование + удаление при перезагрузке |
| Приоритет/нагрузка | `RealTime`, ≈ 31 ГБ чтения за проход | `BelowNormal`; кэш: повторная Полная проверка читает ≈ 1 ГБ вместо ≈ 22 ГБ |
| Приватность | лог можно отправить автору (в этой установке `allowstatistics=1`); проверка обновлений идёт на сторонний сервер | ничего не отправляется; единственный запрос — публичный `version.json` (по желанию) |
| Интерфейс | форма WinForms / консоль | тёмный WPF-интерфейс, RU/EN, граф угрозы, объяснение «что/где/почему/что делать», карантин с восстановлением |
| Обновления | проверка версии; выпуск новой сборки | проверка версии + автообновление правил с проверкой SHA-256 / подписи RSA (проверено автотестами) |

## 4. Где MinerSearch сильнее (честно)

* За ним годы накопленных **IOC конкретных кампаний** (ReaItekHD, WindowsTask, RDPWinst, RMS…) — на настоящем заражении такого семейства он чистит его уверенно; это подтверждено журналами его запусков на тестовой машине с настоящим заражением этого семейства (десятки найденных объектов). У MineHunter такого багажа нет: он ловит **поведение и сочетания признаков**, а списки семейств пополняются через обновления правил (`docs/UPDATES.md`).
* Работа из-под WinPE, ACL-разблокировка объектов, зрелая консольная автоматизация.
* Зрелость: публичный проект с историей релизов; MineHunter — новая программа, проверена автотестами и лабораторией, но не временем и не тысячами реальных машин.

## 5. Что общего и что не сравнивалось

Обе программы — эвристические сканеры по запросу без драйвера ядра. Не сравнивались: реальные образцы вредоносного ПО (запускать их на этом компьютере нельзя; вместо них — безвредная лаборатория), скорость на других конфигурациях, влияние на игры.
