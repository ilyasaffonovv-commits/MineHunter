# Сравнение с MinerSearch v1.4.9.4

Обе программы запускались на одном компьютере (Windows 11 25H2 x64, 24 логических ядра, права администратора) на одном и том же состоянии системы. MinerSearch работал в режиме `-so -cm -v` (только отчёт, без лечения), MineHunter в режиме `scan --quick`. Лаборатория это `tests/MinerLab`: безвредное подобие заражения, каждый объект помечен `MinerLabTest`, все копии «майнера» это разные файлы с разными хешами. Сведения о самом MinerSearch собраны в [MINERSEARCH_RESEARCH.md](MINERSEARCH_RESEARCH.md). Сырые журналы обеих программ в репозиторий не входят.

## 1. Лаборатория

| Сценарий | MinerSearch | MineHunter |
|---|---|---|
| Процесс с командной строкой майнера (пул, пользователь, алгоритм) | Обнаружен, риск 5 (high) | Высокий риск, 84 (полная командная строка это решающая улика) |
| Запущенный `svchost.exe` из `%TEMP%` | Обнаружен, риск 3 | Высокий риск, 76 |
| Запущенный `taskhostw.exe` из `%APPDATA%` | Обнаружен, риск 3 | Высокий риск, 67 |
| `csrss.exe` и `RuntimeBroker.exe` под системными именами, не запущены | Только «нет подписи» | `csrss.exe` входит в находку высокого риска (лежит рядом с запущенным поддельным `svchost.exe`), `RuntimeBroker.exe` подозрительное, 41 |

| Объект с несколькими сигналами (неподписанный, AppData, Run, задача с повтором, ярлык, watchdog-цепочка) | Не помечен | Подозрительное, 57, все звенья в одной находке |
| Высокая нагрузка CPU, 800 МБ ОЗУ, loopback-сокет :3333 сами по себе | Не помечено | Не помечено |
| Копия `notepad.exe` с подписью Microsoft в Temp | Не помечено | Не помечено |
| Цепочка Launcher, Sim, Worker без других улик | Не связывается | Не помечается, связывается в граф при наличии других улик |

Итог MinerSearch на лаборатории по его собственной сводке: 11 угроз, 2 подозрительных, 4 мин 29 с. В журнале с пометкой `[!!!]` есть процесс с командной строкой майнера, два «системных» процесса, служба с образом в Temp и два экземпляра `MineHunter.exe`. Как набралось число 11, журнал не объясняет. Итог MineHunter: 6 находок высокого риска (две из них настоящие остатки прежнего заражения, см. ниже), 5 подозрительных, 25 заметок, быстрая проверка 50–110 с.

## 3. Различия в устройстве

Для MinerSearch данные получены чтением исходников тега `v1.4.9.4` и запусками.

| | MinerSearch | MineHunter |
|---|---|---|
| Основа детекта | Списки IOC конкретных кампаний (пути, имена, аргументы) и узкие эвристики | Улики по категориям, вердикт по совпадению нескольких категорий, правила в открытом JSON |
| Решение | Сумма целых баллов, порог 3 | Балл с потолками категорий, вердикт при совпадении улик разных видов, объяснение «почему не выше» |
| Связь объектов | Нет. Дедупликация по хешу содержимого теряет одинаковые копии | Граф связей, одна находка на всю связку |
| WMI | `CommandLineEventConsumer` с `..\` или `cmd.exe /c` | Все классы потребителей, фильтры, привязки |
| Память | Проверка руткита только семейства r77 и только собственного процесса, в режиме `-so` отключена | Сравнение образа с диском, PE в приватной памяти, потоки вне модулей, приостановленные системные утилиты |
| Сеть и процесс | Нет | Соединения по PID, порты майнинга, домены пулов из DNS-кэша |
| Карантин | Файл режется на блоки по 512 КБ в реестр `HKLM`, ключ это MD5, одинаковые копии перезаписывают друг друга, SHA-256 нет | Своя папка и уникальный id на объект, XOR-маскировка, SHA-256 при записи и восстановлении. Задачи, службы, реестр, WMI, hosts и расширения сохраняются в JSON |
| После лечения | Повторной проверки нет | Повторная проверка, «устранено» только если она подтверждает |
| Приоритет и чтение | `RealTime`, около 31 ГБ чтения за проход | `BelowNormal`. Кэш: повторная полная проверка читает около 1 ГБ вместо 22 ГБ |
| Отправка данных | Лог может быть отправлен автору из окна результатов при включённой статистике. Проверка обновлений идёт на сторонний сервер | Ничего не отправляется, единственный запрос это GET публичного `version.json` |
| Обновления | Проверка версии, новая сборка | Проверка версии и обновление пакетов правил с проверкой SHA-256 и подписи RSA |

## 4. Где MinerSearch сильнее

- У него накоплены IOC конкретных кампаний (ReaItekHD, WindowsTask, RDPWinst, RMS и другие). На компьютере с настоящим заражением такого семейства его журналы показывают десятки найденных и вылеченных объектов. У MineHunter такого объёма IOC нет: он полагается на поведение и сочетания признаков, а списки семейств пополняются обновлениями правил.
- Работа из-под WinPE, снятие ACL с объектов, защищённых вредоносной программой, более зрелый консольный режим.
- Это публичный проект с историей релизов. MineHunter новее, проверен самотестами и лабораторией, а не долгой эксплуатацией.

## 5. Что не сравнивалось

Настоящие образцы вредоносного ПО (запускать их на этом компьютере нельзя, вместо них лаборатория), скорость на других конфигурациях, влияние на игры. Обе программы работают по запросу и не имеют драйвера ядра.
