# Модель оценки риска

Исходное требование: обычная программа не должна попадать в «Высокий риск» из-за одного признака. Высокая загрузка процессора, отсутствие подписи и запуск из `AppData` встречаются у игр, лаунчеров и инструментов разработчика, поэтому такие признаки имеют малый вес, а вердикт «Высокий риск» или «Вредоносное» требует улик нескольких независимых видов. Код: `Risk/RiskEngine.cs`.

## Улики

Каждая улика (`Evidence`) содержит идентификатор правила (`RuleId`), категорию, вес (отрицательный вес означает доверие), текст, подробности и признак `Definitive`. Решающими (`Definitive`) помечены, например, полная командная строка майнера и SHA-256 из списка известного вредоносного ПО. Каталог правил: [RULES.md](RULES.md).

Категории: Signature, Location, Masquerade, Content, Behavior, Network, Persistence, Tamper, Reputation, Trust.

## Подсчёт балла

1. Доверие. У файла с действительной подписью известного издателя, у системного файла Windows и у файла из списка исключений есть отрицательные улики. Они уменьшают собственные положительные улики этого файла в пропорции `(плюсы - доверие) / плюсы`, доверие ограничено 100. Решающие улики не уменьшаются. Для процесса доверие образа не применяется: подпись файла не отменяет поведение процесса (подмену образа, сетевую активность).
2. Одинаковые правила. Если одно правило сработало у нескольких объектов группы, вес берётся один раз и добавляется 15 % за каждое следующее срабатывание, не больше трёх раз.
3. Категории. Внутри категории считается `максимум + 0,5 * сумма остальных`, результат ограничен потолком категории: Signature 15, Location 20, Masquerade 50, Content 75, Behavior 70, Network 40, Persistence 55, Tamper 45, Reputation 100.
4. Итог это сумма по категориям. Известный вредоносный хеш поднимает итог до 100.

Из-за потолков слабые признаки не складываются в большой балл: Signature и Location вместе дают не больше 35.

## Вердикт

Сильные категории: Content, Behavior, Persistence, Network, Masquerade, Tamper, Reputation, если в категории набрано не меньше 12. Signature и Location к сильным не относятся.

| Вердикт | Условие |
|---|---|
| Вредоносное | Балл не меньше 85 и одно из: решающая улика и не меньше двух сильных категорий; не меньше трёх сильных категорий; Reputation на 100 (известный хеш). |
| Высокий риск | Балл не меньше 60 и (решающая улика или не меньше двух сильных категорий), либо решающая улика и балл не меньше 50. |
| Подозрительное | Балл не меньше 30. Если балл не меньше 60, но улики одного вида, отчёт объясняет, почему вердикт не выше. |
| Заметка | Балл от 12 до 29. Показывается отдельно и угрозой не считается. |
| Чисто | Остальное. |

## Находки и граф

Улики привязаны к объектам: файл, процесс, служба, задача, запись автозапуска, WMI-подписка, исключение Защитника, расширение браузера. Между объектами строятся связи: запускает, работает как, запущен из, загружает, ссылается, одна папка, тот же файл, исключён из проверки. Объекты с заметными уликами объединяются по связям в находки, поэтому майнер, его watchdog и записи автозапуска показываются и обезвреживаются вместе.

Объединять группу могут только недоверенные объекты. Доверенный `explorer.exe`, породивший несколько посторонних программ, не склеивает их в одну находку.

## Производные улики

Считаются после сбора данных, когда виден весь граф.

| Правило | Вес | Условие |
|---|---|---|
| `PERSIST.MULTI` | 8 или 20 | Несколько разных механизмов автозапуска (Run, задача, служба, WMI, ярлык) запускают один недоверенный файл: 8 для двух, 20 для трёх и больше. |
| `WATCHDOG.MULTI_PAYLOAD` | 12 | Несколько разных недоверенных программ одной группы стоят в автозапуске. |
| `BEH.CPU_AND_AUTOSTART` | 15 | Фоновая программа держит процессор и сама стоит в автозапуске. |
| `REL.DUPLICATES` | 6 | Точные копии файла в других местах, только если файл уже подозрителен чем-то кроме отсутствия подписи и необычной папки (порог 30 баллов). |
| `PROC.MASQUERADE_RUNNING` | 25 | Сейчас работает процесс с именем системной программы, но файл настоящим не является. |

## Что снижает число ложных срабатываний

- Доверие: подпись Windows и каталога, издатели из `trustedPublishers` в `rules/core.json` (сравнение по началу названия с границей слова, поэтому `Intelligent Systems` не считается `Intel`), образы .NET из кэша NGEN, установщики во временных папках, вспомогательные скрипты подписанных продуктов.
- Тяжёлые программы из `heavyAppNames` (игры, браузеры, компиляторы, виртуальные машины) улик по нагрузке не получают.
- Нагрузка процессора остаётся слабой подтверждающей уликой. Порог: не меньше 22 % всего процессора на машинах с пятью и более логическими ядрами и не меньше 45 % на машинах с четырьмя и меньше, окно измерения 3 секунды. Нагрузка на GPU весит ещё меньше (8).
- Данные не считаются кодом: JSON и текстовые списки блокировки в расширениях браузеров майнером не считаются. Проверяется код (`.js`, `.wasm`, `.html`) и нужно не меньше двух признаков в одном файле, расширения антивирусов и блокировщиков рекламы пропускаются.
- Остатки после чистильщиков (записи планировщика без XML, `TASK.XML_MISSING`) весят 2, а приём с удалённым дескриптором безопасности (`TASK.SD_MISSING`) 40.
- Список исключений (`allowlist.json`, путь и SHA-256) доступен для записи только администраторам.
- Обезвреживание не трогает критические процессы Windows и доверенные системные файлы (`Decision`).

## Как проверить решение

- В окне: вкладка «Результаты», находка, раздел «Почему (улики и баллы)».
- В отчёте `report.json` и `report.txt` те же улики с весами и категориями.
- `MineHunter-cli.exe scan --dump entities.json` записывает все объекты со всеми уликами.
- `MineHunter-cli.exe selftest` содержит проверки оценки: неподписанный файл в Temp с высокой нагрузкой остаётся чистым, один громкий сигнал без подтверждения не выше «Подозрительного» и другие.
