# Модель оценки риска (как MineHunter решает, что опасно)

Главный принцип: **ни один слабый признак не делает программу «вирусом»**. Высокая загрузка процессора, отсутствие подписи, запуск из `AppData` — всё это встречается у обычных программ (игры, лаунчеры, инструменты разработчика, инди-софт). Вердикт «Высокий риск» или «Вредоносное» выдаётся только тогда, когда **сходятся независимые виды улик**.

## 1. Улика (Evidence)

Каждый сигнал — это запись с полями: `RuleId` (стабильный идентификатор), `Category`, `Weight` (вес; отрицательный = «доверие»), человекочитаемый текст и технические подробности, признак `Definitive` («решающая сама по себе», например полная командная строка майнера или SHA-256 из списка известного вредоносного ПО). Полный каталог — в `RULES.md` (115 правил в коде + 17 правил командной строки в `rules/core.json`).

Категории: `Signature` (подпись), `Location` (расположение), `Masquerade` (маскировка), `Content` (содержимое), `Behavior` (поведение), `Network` (сеть), `Persistence` (автозапуск), `Tamper` (вмешательство в защиту), `Reputation` (известные хеши), `Trust` (доверие).

## 2. Подсчёт балла

1. **Доверие.** У файла с действительной подписью известного издателя, системного файла Windows или файла из вашего списка «безопасное» есть отрицательные улики. Они уменьшают *собственные* слабые улики этого файла пропорционально: `масштаб = (плюсы − доверие) / плюсы`. Определяющие (`Definitive`) улики доверием не гасятся. Для **процесса** доверие образа не применяется: подпись файла не отменяет поведение (подмена образа, сеть).
2. **Схлопывание одинаковых правил.** Если одно правило сработало у нескольких участников группы, вес учитывается один раз, плюс +15 % за каждое следующее срабатывание (не больше трёх).
3. **Потолки категорий.** Внутри категории: `максимум + 0,5 × сумма остальных`, затем потолок категории — Signature 15, Location 20, Masquerade 50, Content 75, Behavior 70, Network 40, Persistence 55, Tamper 45, Reputation 100.
4. **Итог** = сумма по категориям (доверие уже учтено в п. 1).

Поэтому куча «слабых» сигналов не складывается в приговор: подпись + расположение вместе не могут дать больше 35 баллов.

## 3. Вердикт и «корроборация»

«Сильные» категории — Content, Behavior, Persistence, Network, Masquerade, Tamper, Reputation (категория считается сильной, если набрала ≥ 12). Signature и Location — только слабые.

| Вердикт | Условие |
|---|---|
| **Вредоносное** (Malware) | балл ≥ 85 **и** (решающая улика + ≥ 2 сильных категории, **или** ≥ 3 сильных категорий, **или** известный хеш) |
| **Высокий риск** (High Risk) | балл ≥ 60 **и** (решающая улика **или** ≥ 2 сильных категории); либо решающая улика и балл ≥ 50 |
| **Подозрительное** (Suspicious) | балл ≥ 30 (если балл ≥ 60, но улики одного вида — в отчёте написано, **почему не выше**) |
| Заметка | балл 12–29: показывается отдельно и **не считается угрозой** |
| Чисто | остальное |

Если вердикт ограничен этим правилом, GUI и отчёт прямо говорят: «Балл высокий, но все улики — одного типа».

## 4. Находка = связанная группа (граф угрозы)

Улики привязаны к объектам: файл, процесс, служба, задача планировщика, запись автозапуска, WMI-подписка, исключение Защитника, расширение браузера… Между объектами строятся связи: «запускает», «работает как» (процесс ↔ образ), «запущен из» (родитель ↔ потомок), «загружает», «ссылается», «одна папка», «тот же файл», «исключён из проверки». Кандидаты (объекты с заметными уликами) объединяются по связям в **находки**. Так майнер, его watchdog и три способа автозапуска становятся одной находкой, а не десятком разрозненных строк, и обезвреживаются вместе.

Связывать группу могут только **недоверенные** объекты: доверенный `conhost.exe` или `explorer.exe`, являющийся родителем нескольких посторонних программ, их в «одну семью» не склеивает.

## 5. Производные улики

Считаются после сбора данных, когда виден весь граф:

* `PERSIST.MULTI` — несколько разных механизмов автозапуска (Run + задача + служба + WMI + ярлык) запускают один и тот же недоверенный файл (8 для двух, 20 для трёх и более);
* `WATCHDOG.MULTI_PAYLOAD` — несколько разных недоверенных программ одной группы стоят в автозапуске (одна перезапускает другую);
* `BEH.CPU_AND_AUTOSTART` — фоновая программа держит процессор и сама стоит в автозапуске;
* `REL.DUPLICATES` — точные копии файла в других местах (только если файл уже подозрителен чем-то кроме «нет подписи/странная папка»);
* `PROC.MASQUERADE_RUNNING` — процесс **сейчас работает** под именем системной/фирменной программы, но файл — не настоящий.

## 6. Что защищает от ложных срабатываний

* **Доверие**: подпись Windows/каталог, известные издатели (Microsoft, NVIDIA, AMD, Intel, Valve/Steam, Discord, Google, Mozilla, JetBrains, Docker, VMware, Oracle и др. — см. `rules/core.json`), образы .NET, собранные самой Windows (NGEN), инсталляторы во временных папках.
* **Тяжёлые программы** (игры, браузеры, компиляторы, ВМ, античиты) не получают улик по нагрузке.
* **Нагрузка процессора** — всегда слабый, лишь подтверждающий сигнал (порог: ≥ 22 % всего процессора на 5+ ядрах, ≥ 45 % на 4 и меньше; измеряется 3 секунды).
* **Данные ≠ код**: файлы-списки блокировки (JSON/текст) в расширениях браузера не считаются майнерами — учитывается только код (`.js`, `.wasm`, `.html`) и как минимум два признака в одном файле; антивирусные расширения и блокировщики рекламы пропускаются.
* **«Мусор» после чистильщиков** (записи Планировщика без XML, `TASK.XML_MISSING`) — вес 2, а по-настоящему опасный приём скрытия задач (удалён дескриптор `SD`, `TASK.SD_MISSING`) — вес 40.
* **Список «безопасное»** (`allowlist.json`, по пути и SHA-256), доступен только администраторам.
* **Обезвреживание** никогда не трогает критические процессы Windows и доверенные системные файлы (проверка в `Decision`).

## 7. Как проверять решения

* GUI: вкладка «Результаты» → любая находка → «Почему (улики и баллы)».
* Отчёт `report.json` / `report.txt`: те же улики с весами и категориями.
* CLI: `MineHunter.exe scan --dump entities.json` пишет **все** объекты сканирования с уликами (для отладки правил).
* `MineHunter.exe selftest` — 60 встроенных проверок, часть из них — калибровка на ложные срабатывания («неподписанный + Temp + высокая нагрузка без остального остаётся «чисто»», «один громкий сигнал без подтверждения — не выше «подозрительное»» и т.д.).
