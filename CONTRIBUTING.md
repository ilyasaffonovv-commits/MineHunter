# Contributing

The most useful contributions are reports of false positives, reports of missed detections and new rules.

## False positives

Use the "False positive" issue template. Attach the finding text from the Results tab (or `report.txt`), the SHA-256 of the file and what the program is. Do not upload private files; the evidence text and the hash are enough.

## Missed detections

Use the "Missed detection" template. Do not attach live malware. Describe the technique (where it persists, how it hides, what its command line looks like) or link a public analysis. `MineHunter-cli.exe scan --full --dump entities.json` writes every object the scan saw, with its evidence.

## Rules

Rules are in [`rules/core.json`](rules/core.json): miner strings, command-line patterns with weight and category, trusted publishers, heavy-app names, path indicators. The scoring code is in `src/MineHunter/Scanning` and `src/MineHunter/Risk`. [`docs/RULES.md`](docs/RULES.md) is generated by `python tests/tools/gen_rules_doc.py`.

- Give a source (public report or sample analysis) in the pull request. Do not add malware hashes without a source that can be checked.
- Weak signals (CPU load, no signature, unusual folder) stay weak. A new strong signal goes into a category with a cap and must be backed by another category before it can reach High Risk.
- Each new rule needs `samples` (`"samples": {"match": [...], "noMatch": [...]}`) with command lines that must and must not trigger it, and a `textRu` translation. The self test runs the samples.
- Do not write miner strings into C# code. The EXE must contain no miner markers, and the self test checks that. Keep such strings in the rule pack; tests build them at run time with `Obf.J("xm", "rig")`.
- Raise `version` in `rules/core.json`. The maintainer signs and publishes the pack with `tools/publish_rules.ps1`.

Before opening a pull request:

```
powershell -ExecutionPolicy Bypass -File build_release.ps1
MineHunter-cli.exe selftest
```

## Code

C# 10, .NET Framework 4.7.2, WPF, no third-party packages. The pipeline is Scanner, Evidence, Analyzer, Risk, Decision, Remediation, Verification. Scanners only read, remediation acts only on a decision plan, and every action is either reversible or marked as not reversible.

## Translations

Interface strings are in `src/MineHunter/Report/Loc*.cs` (English and Russian) and in `L("en", "ru")` calls in the window code.
